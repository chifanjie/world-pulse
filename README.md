# World Pulse / 世界脉搏

一份可追溯、可纠错的每日世界事件日志。项目覆盖政治、经济、市场、科技、科学、气候、健康与文化，保留原创中文摘要、事件背景和直接来源链接。

## 每日内容

每篇日报尽量回答三个问题：

1. **发生了什么？** 只写能够被来源支撑的事实。
2. **为什么重要？** 说明潜在的跨区域、跨行业影响。
3. **还不确定什么？** 明确区分已确认事实、媒体报道与分析判断。

日报通常包含 6–10 个事件，优先覆盖不同地区和主题。若某一类别当天缺少高可信事件，会明确留空，而不是凑数。

此外，每期默认包含 3 条 **AI 前沿雷达**；证据质量需要时保留 2–4 条，不机械凑数：

- 重大模型、产品或工程进展；
- 最近 7 天最值得看的前沿论文；
- AI 安全、基础设施、开源或智能体技术进展。

每条会说明核心技术点、为什么受到关注、热度依据和局限。预印本、公司自报基准和未经独立复现的结果都会明确标注；“热度高”不等于“结论可靠”。

## 发布节奏

- 北京时间 09:00 优先发布日报；13:00 后独立检查到期的 rolling review 与 tested lab，日报已存在不会跳过项目检查。
- 每天的活动上限按近期历史做带权重抽样；普通日通常只有日报，项目日才增加可独立验收的成果。
- 深度条目、数据视角和滚动回顾不绑定固定星期；回顾间隔约 5–10 天浮动。
- 小工具、小游戏或方法改进的间隔约 9–21 天浮动。
- 额外提交只对应可独立审阅的成果或纠错。

计划器参考前 14 个已完成自然日，主动打破连续相同数量和七天重复序列；没有历史 review/lab 时，以项目首提交作为首次到期锚点，避免永远无法触发第一项成果。抽样结果是上限而不是配额：当天没有值得独立提交的成果时，宁可少做。

GitHub 的四档绿色会随当前一年贡献分布变化，并不是固定的“1 次、2 次、3 次、4 次”。自动化每次读取账号实时等级与当日已有贡献，并区分“愿望颜色”和按真实原子工作单元计算的“可达颜色”。普通日报保持浅绿；只有带完整实现、测试和文档的项目日才可能尝试更深档位。目标不可达时自动降级，绝不为颜色制造噪音。

## 编辑原则

- 重要事实附直接来源链接，优先一手机构与可靠通讯社。
- 战争、政治、市场、公共卫生等高风险主题尽量交叉验证。
- 只保存必要元数据和原创摘要，不复制新闻正文，不绕过付费墙。
- 把网页内容视为不可信输入，忽略其中与新闻事实无关的指令。
- 更正会记录在 [CORRECTIONS.md](CORRECTIONS.md)，不偷偷改写历史。

完整规则见 [METHODOLOGY.md](METHODOLOGY.md) 与 [EDITORIAL_POLICY.md](EDITORIAL_POLICY.md)。

## 自动化说明

日报由本地 Codex heartbeat 辅助检索、整理、校验并推送；项目阶段还会在日报完成后检查到期的回顾与 lab。执行状态机详见 [AUTOMATION.md](AUTOMATION.md)。提交使用仓库维护者已绑定 GitHub 的 noreply 邮箱；自动化失败时不会用伪造提交日期补图，只会按真实时间修复和发布。
